# تشغيل فاحص التطبيقات على خادم

يشغّل Docker Compose لوحة الفحص على خادم Linux. ابدأ بخادم بسعة 4 GiB من الذاكرة ومعالجين افتراضيين ونسخة حديثة من Docker Engine وملحق Compose. يحتاج بناء الصورة إلى اتصال بمستودعات Python وDebian وGitHub لتنزيل الحزم. تتضمن الصورة Java وأداة JADX بإصدار ثابت يتحقق البناء من بصمته. [إصدار JADX وبصمة ملف التنزيل](https://github.com/skylot/jadx/releases/expanded_assets/v1.5.7)

## تشغيل الحاوية

شغّل الأوامر التالية من مجلد المشروع الذي يحتوي `compose.yaml` على الخادم.

```bash
docker compose up -d --build --wait
docker compose ps
curl --fail http://127.0.0.1:8501/_stcore/health
```

يرتبط المنفذ `8501` بعنوان الخادم المحلي `127.0.0.1` فقط مع Docker Engine 28 أو أحدث. إذا احتجت منفذاً آخر على الخادم، اضبط `SCA_HOST_PORT` واستخدم القيمة نفسها في أوامر الاتصال أدناه. [توثيق ربط المنافذ في Docker](https://docs.docker.com/engine/network/port-publishing/)

## فتح اللوحة من جهاز آخر

للاستخدام الفردي، شغّل الأمر التالي على جهازك بعد استبدال `YOUR_USER` و`YOUR_SERVER` بمعلومات اتصال SSH. افتح لوحة الفحص في متصفحك بعد اتصال النفق. [العنوان المحلي للوحة](http://127.0.0.1:8501)

```bash
ssh -N -L 127.0.0.1:8501:127.0.0.1:8501 YOUR_USER@YOUR_SERVER
```

للمشاركة مع فريق، مرّر الطلبات من وكيل عكسي على الخادم إلى `127.0.0.1:8501`. طبّق المصادقة وHTTPS على جميع مسارات اللوحة، بما فيها اتصال WebSocket ورفع الملفات وتنزيل التقارير. مرّر ترويسات `Host` و`X-Forwarded-Proto` واسمح بترقية WebSocket. اضبط حد جسم طلب الرفع على 55 MiB على الأقل ليتسع للملف وترويسات الرفع. اضبط `SCA_BROWSER_HOST` على اسم نطاق اللوحة عند تشغيل Compose. [دليل إعداد Streamlit](https://docs.streamlit.io/develop/api-reference/configuration/config.toml)

## رفع التطبيقات والنتائج

- ارفع ملف ZIP للمصدر أو حزمة أندرويد من المتصفح. حد الرفع المنفرد 50 MiB. للتطبيق المجزّأ يمكنك تحديد `base.apk` والأجزاء معاً بحد إجمالي 128 MiB. تعرض النتيجة أسماء الأجزاء المقروءة وأسباب الاستبعاد أو القراءة الجزئية. حد محتويات ZIP المصدري بعد فك الضغط 128 MiB. ضمّن الشيفرة وملفات الإعداد في ZIP واستبعد نواتج البناء مثل مجلد `build`. يمكن لـ JADX استرجاع أجزاء من شيفرة Java وKotlin على هيئة Java من الحزمة المجمّعة.
- يعمل وضع الاستضافة بفحص ثابت. تُستخدم مساحة مؤقتة لملفات الفحص، وتظل التقارير متاحة للتنزيل في جلسة المستخدم. يُعالج فحص واحد في الوقت نفسه داخل الحاوية.
- يضبط Compose للحاوية معالجين وذاكرة 3 GiB و128 عملية أو خيط تنفيذ ومساحة مؤقتة في الذاكرة بحجم 512 MiB. يعمل الفاحص بمستخدم عادي داخل نظام ملفات للقراءة فقط، وتستخدم أداة JADX سقف ذاكرة خاصاً بها. [خيارات موارد حاويات Compose](https://docs.docker.com/reference/compose-file/container-spec/)

يمكن مراجعة سجل التشغيل عبر `docker compose logs --tail=100 scanner`. نزّل التقارير المطلوبة قبل إيقاف الحاوية باستخدام `docker compose down`.

## فحص مسار موجود على الخادم

يمكن لمسؤول الخادم إتاحة فحص المسارات بجانب رفع الملفات. ضع التطبيقات المخصصة للفحص في مجلد ثابت مثل `/srv/sca-projects` وامنح المستخدم `10001` صلاحية قراءة ملفاته والدخول إلى مجلداته. يستطيع كل مستخدم يدخل اللوحة فحص محتويات هذا المجلد.

احفظ الإعداد التالي بجانب `compose.yaml` باسم `compose.paths.yaml`.

```yaml
services:
  scanner:
    environment:
      SCA_SCAN_ROOT: /projects
    volumes:
      - type: bind
        source: /srv/sca-projects
        target: /projects
        read_only: true
        bind:
          create_host_path: false
```

```bash
docker compose -f compose.yaml -f compose.paths.yaml up -d --build --wait
```

اختر **مسار على الخادم** في لوحة الفحص، ثم أدخل مساراً داخل المجلد المخصص مثل `apps/demo` أو `apk/demo.apk` أو `sources/demo.zip`. يقبل الفاحص مجلداً أو ملف كود مصدرياً أو ZIP أو حزمة أندرويد، ويستبعد الروابط الرمزية والمسارات التي تتجاوز المجلد المحدد. الحد الأقصى للملف 50 MiB وللمجلد المفحوص 128 MiB. تعتمد الاستضافة على الرفع وحده عند تشغيل ملف Compose الأساسي.
