# تطبيقات Flutter و Android

تقرأ الأداة تطبيقات Flutter و Android بصورتين: **المشروع المصدري** (مجلد فيه `pubspec.yaml`
و `android/` و `ios/`)، و**حزمة التطبيق المبنية** (`.apk` أو `.aab` أو `.apks` أو `.xapk` أو
`.apkm`). والتحليل في الحالتين ستاتيكي: تُفكّ الحزمة وتُقرأ ببايثون، ولا تُثبَّت على جهاز ولا
تُشغَّل ضمن الفحص الثابت. أما تبويب [التحليل أثناء التشغيل](DYNAMIC_ANALYSIS.md) المستقل
فيثبّت التطبيق ويرصده على مختبر Android عند اختيار بدء التسجيل.

> تحديث 2026-11-27: تعرض الواجهة والمعاينة وتنزيلاتها وأرشيف الأدلة المحلي القيم الأصلية كاملة.
> الإشارات إلى إخفاء القيم في الأقسام القديمة أدناه تخص تمثيل التحليل والذكاء الاصطناعي
> وسطر الأوامر. تفاصيل قوالب الروابط ومواقع الموارد ومعرّفات SDK وحدود قراءة المكتبات
> الأصلية في [تقرير التحقق الحالي](VALIDATION_2026_11_27.md).

النسخة الإنجليزية: [FLUTTER.md](FLUTTER.md). النتائج المقاسة:
[evaluation/flutter_results.md](../evaluation/flutter_results.md).

```bash
python -m sca scan path/to/flutter_app                 # مشروع مصدري
python -m sca scan app-release.apk --format html,json   # حزمة تطبيق
python -m sca flutter info app-release.apk              # معلومات الحزمة
python -m sca flutter deps path/to/flutter_app          # حزم Dart وثغراتها المعروفة
python -m sca flutter apis app-release.apk              # عناوين الخوادم واستدعاءات API والمفاتيح
python -m sca flutter decode app-release.apk --out decoded   # كتابة الملفات المفكوكة
```

## 1. ماذا يُحلَّل

### 1.1 في المشروع المصدري

| الجزء | الملفات | الطريقة |
|---|---|---|
| كود Dart | `lib/**/*.dart` (وتُتجاوز الملفات المولَّدة `*.g.dart` و `*.freezed.dart` و `*.mocks.dart` و `*.gr.dart`) | 47 قاعدة أنماط `DART-*`؛ ومحرك الأسرار، ومعه صيغتا مفاتيح خاصتان بـ Dart من نوع `kind: secret` (DART-SECRET-001 و DART-SECRET-003)؛ وتتبّع المدخلات (taint-lite) بمصادر خاصة بـ Dart مثل `TextEditingController.text` ومعاملات الروابط العميقة و `Uri.base` |
| ملفات البناء و Firebase والويب | ملفات CI و `*.sh`، و `firestore.rules` و `storage.rules` و `database.rules.json`، و `web/index.html` | 5 قواعد `FLUTTER-*` تحدد الملفات التي تنطبق عليها (الحقل `files`) |
| إعدادات Android | `android/app/src/main/AndroidManifest.xml` وطبقة `src/release/` فوقه، و `res/xml/*.xml`، و `build.gradle(.kts)`، و `key.properties`، وملفات مخازن المفاتيح | فحوص بنيوية (المحرك `flutter`): يُحلَّل ملف XML بنيوياً ولا يُطابَق سطراً سطراً |
| إعدادات iOS | `ios/Runner/Info.plist` و `macos/Runner/Info.plist` | فحوص بنيوية بمكتبة `plistlib` |
| الاعتماديات | `pubspec.yaml` و `pubspec.lock` | مقارنة بقائمة منتقاة من 25 تنبيهاً أمنياً لـ 23 حزمة Pub، وقائمة بـ 16 حزمة متوقفة (`sca/flutter/data/`) |

ملفات manifest الخاصة بالتصحيح والقياس والاختبار (`src/debug/` و `src/profile/`، وتركيباتها مع
النكهات مثل `src/prodDebug/`) تُذكر في الحقائق ولا تُعامَل كملفات manifest للإصدار؛ وكل مجموعة
مصادر أخرى، ومنها نكهات المنتج (product flavors) مثل `src/prod/` و `src/prodRelease/`، تُعدّ من
الإصدار. ويُعرَف المشروع من ملف `pubspec.yaml` يعتمد على Flutter SDK، أو من ملف
`src/main/AndroidManifest.xml` بجانب ملف وحدة Gradle، فتشمل فحوص Android أيضاً مشاريع Android
العادية المكتوبة بـ Java أو Kotlin. ووحدة المكتبة في Android (`com.android.library`) تُدمج لاحقاً
في تطبيق، فلا يُفحص منها إلا مكوّناتها وصلاحياتها وروابطها وإعدادات أمان الشبكة، دون خصائص
`<application>` ومستويات SDK. أما مجلدا `android/` و `ios/` في إضافة Flutter (plugin)، أي الحزمة
التي في ملف `pubspec.yaml` الخاص بها المفتاح `flutter: plugin:`، ففيهما كود الإضافة الخاص بكل
منصة، فلا يُفحصان كتطبيق.

### 1.2 في حزمة التطبيق

تتحوّل الحزمة إلى **ملفات افتراضية**: نصوص محفوظة في الذاكرة، لكل منها مسار وأسطر، فتعمل
عليها المحركات وتشير إليها النتائج كما لو كانت ملفات مصدرية. ويخبر حقل `origin` في كل ملف
المحركاتِ بنوعه.

| الملف الافتراضي | مصدره | النوع (origin) | من يقرؤه |
|---|---|---|---|
| `AndroidManifest.xml` | XML ثنائي (APK) أو XML بصيغة protobuf (AAB)، تُكتب كلُّ خاصيةٍ (attribute) منه في سطر | decoded | القواعد، الأسرار، الفحوص |
| `res/xml/<name>.xml` | موارد XML بأسمائها المنطقية، حتى حين يختصر R8 اسم الملف (`res/8G.xml`) | decoded | القواعد، الأسرار، الفحوص |
| `res/values/strings.xml` | النصوص من `resources.arsc` (ومن `resources.pb` في AAB)، كل نص في سطر | decoded | القواعد، الأسرار |
| `assets/...` | الأصول النصية مثل ملفات `.env` و JSON | decoded | القواعد، الأسرار، الفحوص |
| `dart/lib/<path>.dart` | كود Dart المصدري المستعاد من `kernel_blob.bin` (في نسخ التصحيح فقط) | recovered | القواعد، الأسرار، تتبّع المدخلات، الذكاء الاصطناعي |
| `lib/<abi>/libapp.so` | نصوص لقطة Dart المترجمة مسبقاً AOT (نسخ الإصدار و profile) | strings | الأسرار، الفحوص |
| `classes.dex` و `classes2.dex` ... | نصوص DEX (مع حذف واصفات الأنواع ونصوص المترجم الأخرى) | strings | الأسرار |
| `lib/<abi>/<other>.so` | النصوص المقروءة من المكتبات الأصلية الأخرى | strings | الأسرار |
| `jadx/<package>/<Class>.java` | أصناف التطبيق نفسه بعد فك ترجمتها بـ jadx (اختياري) | decompiled | القواعد، الأسرار، الذكاء الاصطناعي |
| `_sca/signing.txt` و `_sca/build.txt` و `_sca/packages.txt` | حقائق تكتبها الأداة نفسها | summary | الفحوص فقط |

ملفات النصوص المستخرجة لا تُعطى لقواعد الأنماط (لأن نصاً ثابتاً في مكتبة ليس كوداً)، ولا
تُحسب أسطراً من الكود في درجة المشروع. ولا يقرأ نصوص DEX ونصوص المكتبات الأصلية الأخرى إلا محرك
الأسرار وجرد واجهات API والمفاتيح؛ ومن بين ملفات النصوص كلها لا تقرأ الفحوص البنيوية إلا نصوص `libapp.so` (الفحصان
FLUTTER-APP-007 و FLUTTER-APP-008). وملفات الملخص لا يقرؤها محرك الأسرار، فلا تُعدّ بصمة
الشهادة مفتاحاً مسرَّباً. وكل ما في حزمة التطبيق يصل إلى مستخدميه، فلا يُعامَل أي ملف منها
ككود اختبار مهما كان اسم مجلده.

**درجة حزمة التطبيق** تُحسب من الأسطر التي نوعها decoded أو recovered أو decompiled فقط (ملف
manifest، والموارد، والأصول النصية، وكود Dart المستعاد من نسخة التصحيح، ومخرجات jadx). ونسخة
الإصدار لا مصدر مستعاداً فيها، فأسطرها قليلة: تُقسَم العقوبة حينئذ على الحد الأدنى، وهو نصف ألف
سطر، فتكفي نتائج قليلة لتنخفض الدرجة كثيراً. لذلك تأتي درجة حزم الإصدار منخفضة غالباً، فقارن
بين الحزم بنتائجها لا بدرجتها.

## 2. كيف تُفكّ حزمة التطبيق

الدالة `load_app` في `sca/flutter/apk.py` تنفّذ الخطوات التالية. كل خطوة محمية: الجزء التالف
أو المعادي يصبح تحذيراً في الحقائق وتستمر بقية الخطوات.

1. **الحاوية.** قارئ ZIP خاص بالمشروع (`zipread.py`) يقرأ الدليل المركزي ويفكّ الضغط بحدّ
   أقصى للحجم، ولا يكتب أي ملف من الحزمة على القرص باسمه الأصلي. ويسجّل الحيل التي تُربك
   الأدوات الأخرى: الأسماء المكررة، والأسماء التي لا تختلف إلا في حالة الأحرف، وتعدد سجلات
   نهاية الأرشيف، وعلامة التشفير. ملف `.aab` أرشيف واحد فيه مجلدات للوحدات (`base/manifest/`
   و `base/dex/` ...)، ومجموعة APK فيها حزمة أساسية وحزم مقسّمة حسب المعمارية (ABI).
2. **جدول الموارد.** يعطي `resources.arsc` (الوحدة `arsc.py`) أسماء معرّفات الموارد، والأسماء
   المنطقية لملفات الموارد المختصرة، ونصوص التطبيق.
3. **ملف manifest.** يُفكّ XML الثنائي (`axml.py`)، وتُؤخذ أسماء الخصائص من معرّفات الموارد كما
   يفعل نظام Android، لا من جدول النصوص؛ فلو غُيِّر اسم خاصية مثل `android:debuggable` في جدول
   النصوص لبقيت الأداة تعرفها. وفي AAB يكون الملف بصيغة protobuf (`aabproto.py`). ويُكتب الناتج
   خاصيةً في كل سطر، فتشير النتيجة إلى الخاصية نفسها.
4. **موارد XML** (إعدادات أمان الشبكة، ومسارات FileProvider) و**النصوص**.
5. **الأصول.** الأصول النصية (`.env` و JSON و YAML ...) حتى 1 MiB لكل ملف. ويعطي
   `NOTICES.Z` أسماء الحزم حين لا تذكرها اللقطة.
6. **Flutter.** نسخة التصحيح تحمل `assets/flutter_assets/kernel_blob.bin`، ومنه تستعيد
   `kernel.py` كود Dart المصدري لحزمة التطبيق نفسه، مع إصدارات الحزم ومسارات جهاز البناء.
   ونسخة الإصدار أو profile تحمل `lib/<abi>/libapp.so`، فتقرأ `snapshot.py` ملف ELF، وترويسة
   اللقطة (بصمة الإصدار والخصائص التي تحدد نوع البناء: `product` تعني نسخة إصدار)، ونصوص
   Dart، وعناوين `package:` (ولا يبقى منها في النسخة المموَّهة إلا القليل: 4 في النسخة المموَّهة
   من التطبيق التجريبي)، ووجود رموز التصحيح. ويُحكم على التمويه من نسبة الأسماء الخاصة القصيرة
   (مثل `_Xb@...`) لا من هذه العناوين. ويعطي `lib/<abi>/libflutter.so` إصدار Dart ورقم مراجعة
   المحرّك.
7. **DEX.** تقرأ `dex.py` جداول النصوص والأنواع والأصناف: أصناف الإضافات (plugins)، وعلامات
   Flutter، وملف النصوص.
8. **التوقيع.** تقرأ `signing.py` توقيعات v1 (JAR) و v2 و v3 و v3.1، وتحلّل الشهادات (الجهة،
   ومدة الصلاحية، والمفتاح، وخوارزمية التوقيع، وهل هي شهادة التصحيح)، وتكتب أسماء الجهات بالترتيب
   الذي يستخدمه apksigner و keytool (`C=US, O=Android, CN=Android Debug`). ولا تتحقق من التوقيع
   تشفيرياً؛ هذا عمل apksigner حين يكون مثبّتاً مع الخيار `--apk-tools`.
9. **المكتبات الأصلية الأخرى** للمعمارية المفضّلة (arm64-v8a ثم armeabi-v7a ثم x86_64 ثم
   x86): نصوصها المقروءة، بحدّ أقصى 10 مكتبات.
10. **الملخصات.** تحفظ `_sca/build.txt` و `_sca/signing.txt` و `_sca/packages.txt` الحقائق
    أسطراً بصيغة `Label: value`، فيكون لكل نتيجة عن البناء أو التوقيع ملف وسطر.
11. **الأدوات الاختيارية** (`--apk-tools`): يفكّ jadx ترجمة أصناف حزمة التطبيق ومكوّنات ملف
    manifest، ويتحقق apksigner من التوقيع.

حدود تحمي الأداة من الحزم المعادية: 64 MiB من النص المفكوك لكل تطبيق، و 300 مورد XML، و 20,000
نص، و 2,000 أصل نصي، و 100 ملف DEX، و 200,000 سطر لكل ملف نصوص من DEX أو من `libapp.so`،
و 100,000 سطر لنصوص كل مكتبة أصلية أخرى، وأسطر أقصر من 600 حرف بلا محارف تحكّم. ولا يُقرأ أي جزء
إلا حتى حدّ أقصى لحجمه، ويعمل قرّاء الصيغ ضمن ميزانيات محددة (بايتات النصوص المفكوكة، والأسماء
والعناوين المفحوصة)، فلا تستطيع حزمة مصنوعة بجداول متداخلة أو ضخمة أن تُطيل عملها. وتُحذف محارف
التحكم في اتجاه النص (Unicode bidi) الآتية من التطبيق من كل المخرجات (النتائج والحقائق والتقارير
والطرفية)، فلا تستطيع أن تغيّر ترتيب ما يراه القارئ. وفي الواجهة تُضاف إلى نصوص التطبيق التي تُعرض
بصيغة Markdown (التنبيهات والتسميات) علامة WORD JOINER غير مرئية، فلا يتحوّل عنوان أو بريد إلكتروني
فيها إلى رابط.

| jadx بإصدار 1.4 أو أحدث (يحتاج Java 11 أو أحدث) | مع `--apk-tools`: تفكّ ترجمة أصناف حزمة التطبيق ومكوّنات ملف manifest (2,000 صنف على الأكثر) إلى ملفات Java باسم `jadx/...`، وتُحفظ النتيجة لكل تطبيق في مجلد البيانات فلا تتكرر | `SCA_JADX` ثم `JADX_HOME` ثم `PATH` |

لا تُعطى jadx و apksigner إلا مسارات أنشأتها الأداة، مع حدّ زمني (300 ثانية و 120 ثانية)،

## 7. جرد واجهات API والمفاتيح

بعد حساب الدرجة يحصر الفحص الخوادم التي يتصل بها التطبيق والمفاتيح التي يحملها
(`sca/flutter/inventory.py`، والخطوة *جرد API* في سلسلة الفحص). ويفعل ذلك في حزم التطبيقات وفي
مشاريع Flutter و Android المصدرية. وكل شيء يُقرأ من النصوص التي في الفحص أصلاً: لا يُتصل بأي
عنوان. وكل سرّ يُخفى جزئياً (`sca.walker.mask_secret`) في الحقائق والتقارير والواجهة والطرفية.
والإخفاء يشمل الفحص كله: بعد عمل المحركات يُخفي كل ملف كل أسرار الفحص، فالسرّ الذي يُكتشف في ملف
يُخفى في مقاطع الكود وسياقها في كل نتيجة، وفي الحقائق والجرد وطلبات الذكاء الاصطناعي ومتعلّم
القواعد. والأسرار التي تُخفى هكذا: قيم محرك الأسرار (وفي ملف `.env` القيم التي يبلّغ عنها هو
بالضبط)، وقيم نتائج بيانات الاعتماد الأخرى، وما تحمله العناوين ظاهراً: قيم معاملات المفاتيح
والرموز في العنوان، وكلمة المرور في `user:password@` (ومنها `redis://:pw@host`)، ورموز Webhook
والبوتات. وقيمة نتيجة بيانات الاعتماد الأخرى تؤخذ من موضع تطابق القاعدة نفسها
(`SecretKey('...')` حتى لو سبقه نص ثابت آخر في السطر)، ومن إعداد توقيع في Gradle أو
`key.properties` (`keyPassword` و `storePassword`، لا `keyAlias`)، وفي السطر الذي يقرأ قيمة
باسمها لا تؤخذ إلا القيمة المكتوبة بجانبه (`defaultValue: '...'` في `String.fromEnvironment`،
و `--dart-define=NAME=value`). وكل قيمة تُخفى في ملفها، ولا تُشارَك مع بقية ملفات الفحص إلا إذا
كانت قوية: 8 أحرف أو أكثر، وليست كلمة عادية واحدة، وليست أرقاماً فقط، وليست منتظمة جداً (إنتروبيا
شانون 2.5 أو أكثر). فالقيمة القصيرة أو العادية، مثل كلمة مرور مخزن مفاتيح التصحيح `android` أو
كلمة المرور `admin` في عنوان، لا تُخفي هذه الكلمة في مكان آخر. والنتيجة في
`ScanResult.app["apis"]` (أي `facts["apis"]`).

## 8. سطر الأوامر والواجهة

- يقبل `python -m sca scan PATH` مجلداً أو ملفاً أو حزمة تطبيق. الخيار `--no-flutter` يوقف
  الفحوص البنيوية، ويحذف أيضاً في المشروع المصدري حقائق التطبيق وجرد واجهات API والمفاتيح، أما
  حزمة التطبيق فتحتفظ بهما. و `--apk-tools` يضيف jadx و apksigner. ولا تعمل Bandit و Semgrep و Gitleaks
  على حزم التطبيقات (لأنها تقرأ ملفات من القرص). وفي هدف جوال يطبع الملخص أيضاً سطر `APIs   :`
  والتنبيهات الخطيرة (danger) من الجرد.
- `python -m sca flutter info|decode|deps|apis|tools [PATH] [--out DIR] [--json]
  [--apk-tools] [--exclude a,b]`: يطبع `info` الحقائق وسطراً واحداً يلخّص الجرد (أو ملاحظة
  `Note:` إذا تعذّر بناء الجرد)، و `deps` حزم Dart ومشكلاتها، و `apis` الجرد (الملخص، ثم
  التنبيهات، ثم كل قائمة بمواضعها؛ ومع `--json` يطبع `facts["apis"]`)، ويكتب `decode` كل ملف
  افتراضي مع `facts.json`، وفيه الجرد أيضاً، في مجلد فارغ (رمز الخروج
  0، أو 1 إذا تعذّرت كتابة ملف، أو 2 لخطأ في الاستخدام)، ويعرض `tools` الأدوات الاختيارية. ويمكن
  أن تأتي الخيارات قبل الإجراء والمسار أو بعدهما (`flutter decode app.apk --out decoded`
  و `flutter --out decoded decode app.apk` سواء). وتُكتب أحجام الحزم بالوحدات العشرية
  (1 MB = 1,000,000 بايت)، كما في جداول التقييم.
- من تبويب **مصدر الفحص** اختر مجلداً أو ملفاً أو ارفع أرشيفاً. لتطبيق مجزّأ، اختر
  مجلده أو ارفع ملفاته معاً. تجد **عيّنة Flutter** في تبويب **العيّنات**، وتختار
  `samples/flutter_vulnerable_app`. والمفتاحان هما **فحوص Flutter و Android** و**فك ترجمة ملفات
  التطبيق والتحقق منها (jadx و apksigner)**. وبعد الفحص يعرض تبويب اللوحة لوحة التطبيق (الحزمة،
  والإصدارات، ونوع البناء، ومستويات SDK، والتوقيع، والصلاحيات، والمكوّنات، والروابط العميقة،
  والحزم، وتحذيرات فكّ الحزمة) ورسمين حسب OWASP Mobile Top 10 ومجموعات MASVS. وتحت لوحة التطبيق
  قسم **واجهات API والمفاتيح: N عنوان خادم، N مفتاح، N تنبيه خطير** فيه الجرد: الأعداد،
  والتنبيهات في مربعات ملوّنة، وتبويبات عناوين الخوادم، والمفاتيح، والخوادم، واستدعاءات API،
  ومسارات API، ومعرّفات الخدمات (ومعها مشروع Firebase)، وقيم ملفات env.، والزر **نزّل الجرد
  (JSON)**. وهو يحلّ محلّ قائمة عناوين الخوادم البسيطة التي كانت في لوحة التطبيق. وفي تبويب
  التعليمات صفحة **Flutter و APK** فيها جدولا الفحوص والقواعد وشرح هذا القسم.
- في **عناوين الخوادم** اضغط على العنوان ليظهر الملف والسطر في المعاينة الجانبية.
  إذا ظهر العنوان في أكثر من موضع، اختر واحداً من **المواضع المسجّلة**. تعمل النقرة نفسها
  في **مسارات API** و**استدعاءات API**. يفتح الاستدعاء عند سطر الطلب، ويمكن الانتقال
  إلى سطر وسيطة العنوان إذا تعرّف عليها الفاحص في سطر آخر. في النصوص المستخرجة من ملف
  ثنائي، يشير رقم السطر إلى قائمة النصوص التي تقرؤها في المعاينة.
- عند اختيار مسار `base.apk` على الجهاز، يعرض الفاحص أسماء الأجزاء المجاورة ويحدد
  خيار تضمينها تلقائياً. ألغِ تحديد الخيار إذا أردت الاقتصار على الملف الأساسي.
- يبدأ تبويب **النتائج** بعرض جميع درجات الخطورة وحالات المراجعة. عند تطبيق مرشّح،
  يظهر عدد النتائج المخفية. يعيد زر **عرض كل النتائج** ضبط المرشّحات والبحث.
- عند فحص مجلد السورس على جهازك، اضغط على النتيجة في تبويب **النتائج** لقراءة السطر
  المميز من الملف الأصلي، بما فيه قيمة المفتاح المكتوبة في السطر. إذا تغيّر الملف
  منذ الفحص، تعرض الواجهة تنبيهاً حتى تعيد الفحص وتحدّث موضع النتيجة.
- بعد فحص حزمة محلياً، انقر صف المفتاح في **واجهات API والمفاتيح** أو صف النتيجة في
  **النتائج**. تظهر معاينة جانبية مع مسار الملف والسطر المحدد مميّزاً. استخدم
  **تصفّح الملفات المفكوكة** من المعاينة لفتح الموضع في المتصفح الكامل. تعرض المعاينة النص
  المفحوص وقيم المفاتيح مباشرة، مع إبراز السطر المحدد كاملاً. يحفظ الأرشيف المحلي نسخة الأدلة
  بشكل منفصل لاستعادتها عند فتح الفحص لاحقاً. أعد الفحص لفتح الملفات من نتيجة قديمة حُفظت دون أدلة.
- في المعاينة يظهر اسم ملف APK الذي احتوى الدليل إذا كان الإدخال مجزأً. سطر ملف مصدر
  يخص النص المفحوص، وسطر DEX أو المكتبة الثنائية يخص قائمة النصوص التي استخرجها الفاحص.
  لا تحتاج إلى رفع ملف سورس إضافي أو إدخال المفتاح كي تراه. العرض لا يتصل بمزوّد الخدمة؛
  ظهور المفتاح وحده لا يثبت صلاحياته أو قابلية استغلاله.
- يعرض جدول **واجهات API والمفاتيح** القيم الأصلية كاملة، وكذلك التقارير المنزّلة من جلسة
  الفحص الجديدة. يستخدم البحث النص الأصلي للسطر، وتبقى هوية النتيجة ثابتة عند مراجعتها.
  يحفظ الأرشيف الجديد النصوص المفحوصة والقيم الأصلية دون مسارات لإعادة فتح الملفات المحلية.
  تبقى سجلات الأرشيف القديمة التي لا تحتوي الأدلة بحاجة إلى إعادة فحص لاستعادة القيم،
  وتبقى تقارير سطر الأوامر بصيغتها السابقة.
- في **السجل** يظهر مسار قاعدة بيانات الأرشيف ومسار كل إدخال وتاريخه. يمكن البحث باسم
  الملف أو المسار، أو فتح نتيجة محفوظة، أو اختيار المسار لفحصه مجدداً بعد تغيير الملفات.
- التقارير: في تقرير HTML قسم *APIs and keys* (سطر الملخص، والتنبيهات، والجداول، وملاحظة إذا
  اختُصرت قائمة)، وفي تقرير PDF المحتوى نفسه نصاً، وفي SARIF الملخص والتنبيهات وأعداد `truncated`
  في `run.properties.apiInventory`، وفي تقرير JSON الجرد كاملاً في `app.apis`.

## 9. التقييم

يكتب `python evaluation/flutter_eval.py` الملفين `evaluation/flutter_results.md` و `.json`،
بالمحركات الستاتيكية فقط ودون ذكاء اصطناعي.

| القياس | النتيجة |
|---|---|
| عيّنات Flutter (60 ثغرة موسومة، منها ثغرتان صعبتان، و 5 أسطر آمنة تشبه المصاب، مع تطبيق آمن)، كل المحركات الستاتيكية | Precision 1.000 و Recall 0.983 و F1 0.992 (59 صحيحة، 0 كاذبة، 1 فائتة) |
| العيّنات نفسها، بقواعد الأنماط والأسرار فقط (دون فحوص Flutter) | Precision 1.000 و Recall 0.550 |
| العيّنات نفسها، الوضع الصارم | Precision 1.000 و Recall 0.233 |
| DVMA، 218 وحدة (استرجاع على مستوى الوحدة) | 26 وحدة (11.9%)، و 75 وحدة في مجلدها نتيجة ما |
| DVMA حسب نوع الفئة: *كود* / *تصميم* / *سلوك وقت التشغيل والذكاء الاصطناعي* | 26.2% / 10.0% / 4.3% |
| Ostorlab Insecure Flutter، 16 ملفاً | 15 ملفاً (93.8%) |
| DVFA، 10 تحدّيات | 5 تحدّيات (50%)، و 5 من السبعة غير المعلَّمة بأنها صعبة |
| التطبيق التجريبي، الثغرات المزروعة المكتشَفة | المصدر 16/16، debug 16/16، release 14/16، المموَّه 14/16، aab 14/16 |
| تطبيق API التجريبي، بنود الجرد المذكورة | المصدر 21/21، debug 22/22، release 24/24، المموَّه 24/24 |

كيف تُقرأ الأرقام: العيّنات والتطبيقان التجريبيان كُتبت مع الأداة، فهي تثبت أن الوحدة تعمل من
البداية إلى النهاية، ولا تقيس أداءها على كود لم تره. أما المختبرات فكتبها آخرون، وملفات
الإجابات الصحيحة لها (`evaluation/flutter_truth/`) كُتبت لهذا التقييم من توثيق كل مختبر، مع ملف
كل بند وسطره. ومختبر DVMA كبير، وأغلب وحداته ثغرات تفويض واتصال بين التطبيقات (IPC) ووكلاء ذكاء
اصطناعي وغياب دفاعات وقت التشغيل، وهذه لا يراها فحص أنماط ولا فحص بنيوي ستاتيكي (يصنّف الملف
`evaluation/flutter_truth/dvma.json` كل فئة). وتكتشف الأداة إعداداته على مستوى التطبيق كله
(مكوّنات مُصدَّرة، واتصال غير مشفّر، ونسخ احتياطي، وملف manifest للإصدار قابل للتصحيح)، لكنها
لا تخص وحدة بعينها، فتُعرض منفصلة. وارتفع Ostorlab من 10 إلى 15 ملفاً من 16 بقواعد Dart الأربع
التي أُضيفت مع الإصلاحات الأخيرة (DART-CMD-003 للبندين O03 و O07، و DART-CRYPTO-010 للبند O08،
و DART-STORAGE-006 للبند O09، و DART-CODE-002 للبند O12). وقد كُتبت هذه القواعد بعد أن عُرفت تلك
الثغرات الفائتة، فلم يعد Ostorlab اختباراً على كود لم تره الأداة في هذه الملفات الخمسة. والملف
الوحيد الذي ما زال يفوتها (O10: ثغرة padding oracle، أي AES-CBC مع PKCS7 دون MAC) يحتاج معرفة أن
المدخل يُفكّ تشفيره دون التحقق من سلامته، وهذا لا تراه قاعدة تفحص سطراً واحداً.

وارتفع الاسترجاع في عيّنات Flutter من 0.967 (58 صحيحة، 0 كاذبة، 2 فائتة) إلى 0.983 حين صار محرك
الأسرار يقرأ أسطر `NAME=value` غير المحاطة بعلامات تنصيص في ملفات `.env`: فالبند M27 (سرّ في
ملف `.env`) يُكتشف الآن، وقواعد الأنماط والأسرار وحدها انتقلت من 32 إلى 33 نتيجة صحيحة (الاسترجاع
من 0.533 إلى 0.550). والثغرة الوحيدة التي ما زالت تفوت الأداة هي D30 (CWE-598: رمز دخول في معاملات
عنوان URL). لا قاعدة تبلّغ عنها؛ والجرد يرفع لها تنبيه «مفتاح في العنوان»، لكن التنبيه ليس نتيجة.

**جرد واجهات API والمفاتيح.** `samples/flutter_api_probe` تطبيق Flutter مليء بعناوين الخوادم
والمفاتيح، ويذكر الملف `evaluation/flutter_truth/api_probe.json` بنوده الخمسة والعشرين والفحوص التي
يُنتظر فيها كل بند. ولا يُنتظر البند إلا حيث يمكن أن يوجد: المفتاح المكتوب على أجزاء
(`'sk_' 'live_' '...'`) لا يكتمل إلا في نسخة الإصدار، ومفتاح Google Maps الذي يدمجه Gradle
(`manifestPlaceholders`) لا يوجد إلا في ملف manifest المبني، والاستدعاءات لا توجد إلا حيث يوجد نص
الكود. الجدول الكامل في القسم 6 من [flutter_results.md](../evaluation/flutter_results.md).

| الفحص | البنود المذكورة | العناوين | الخوادم | المفاتيح (السرية) | الاستدعاءات | مسارات API | معرّفات الخدمات | قيم ملفات env. | التنبيهات (خطر / تحذير / معلومة) |
|---|---|---:|---:|---:|---:|---:|---:|---:|---|
| المصدر | 21 من 21 | 15 | 15 | 5 (4) | 12 | 5 | 12 | 3 | 9 / 5 / 4 |
| debug.apk | 22 من 22 | 15 | 15 | 6 (5) | 12 | 5 | 13 | 3 | 12 / 4 / 4 |
| release.apk | 24 من 24 | 18 | 16 | 10 (8) | 0 | 3 | 13 | 3 | 15 / 4 / 5 |
| release_obf.apk | 24 من 24 | 18 | 16 | 10 (8) | 0 | 3 | 13 | 3 | 15 / 4 / 5 |

تذكر نسخة الإصدار مفاتيح أكثر من المصدر، لأن المترجم يدمج المفاتيح المكتوبة على أجزاء. والتمويه
لا يغيّر شيئاً في الجرد. ولا استدعاءات في نسختي الإصدار، لأنهما لا تحتفظان بنص الكود.

لإعادة القياس:

```bash
python evaluation/flutter_eval.py                         # العيّنات والمختبرات
python infected_project/fetch_labs.py                     # ينزّل DVMA و DVFA و Ostorlab (وبقية المختبرات)
python tools/build_flutter_apks.py --out ../probe_apks --modes debug,release,obfuscated,aab
python evaluation/flutter_eval.py --apks ../probe_apks    # يضيف جدول «ماذا يبقى بعد الترجمة»
python tools/build_flutter_apks.py --app flutter_api_probe --out ../api_apks --modes release,obfuscated,debug
python evaluation/flutter_eval.py --api-apks ../api_apks  # يضيف الحزم إلى جدول الجرد
```

ينسخ `tools/build_flutter_apks.py` المجلد `samples/flutter_apk_probe` (أو تطبيق API التجريبي مع
الخيار `--app flutter_api_probe`) إلى مجلد مؤقت، ويضيف ملفات القالب بالأمر `flutter create`،
ويبني دون اتصال إذا كانت الذاكرة المؤقتة (cache) لـ Gradle وللمحرّك موجودة على الجهاز (وإلا فمع
الخيار `--allow-downloads`). ولا يكتب شيئاً داخل المستودع. لا تثبّت الحزم المبنية ولا تشغّلها.
ويفحص `tests/test_flutter_inventory.py` حزم تطبيق API التجريبي إذا دلّ `SCA_FLUTTER_API_DIR` على
المجلد الذي فيه `release.apk` و `release_obf.apk` و `debug.apk`.

## 10. الحدود

- تُقرأ نسخة الإصدار من نصوصها لا من تعليمات الآلة: الثغرات التي هي بنية في الكود (دالة TLS،
  أو تدفق بيانات إلى السجل أو إلى استعلام) لا تُكتشف إلا في المصدر أو في نسخة التصحيح. ففي
  التطبيق التجريبي ضاع في نسخ release والمموَّهة و AAB دليلُ دالة TLS ودليلُ كتابة رمز الدخول في
  السجل، ولم يبقَ إلا النصوص.
- يُفحص كود Dart سطراً سطراً مع تتبّع تقريبي للمدخلات داخل الملف الواحد؛ لا يوجد محرك تدفق
  بيانات للغة Dart، ولا مخطط استدعاءات يربط Dart بكود Kotlin أو Java (قنوات المنصة). والقاعدة
  DART-TLS-002 لا تنظر إلا إلى السطر الذي يلي بداية الدالة مباشرة، فإن جاء قبل `return true` سطرُ
  تسجيل (log) فاتتها الثغرة.
- القاعدة FLUTTER-BUILD-001 تفحص أمر `flutter build` المكتوب في سطر واحد؛ أما الأمر الممتد على
  عدة أسطر بالعلامة `\` فلا يُفحص.
- درجة حزمة التطبيق لا تحسب إلا الأسطر من نوع decoded و recovered و decompiled (القسم 1.2)، لذلك
  تأتي درجة حزم الإصدار منخفضة غالباً بسبب نتائج قليلة.
- منطق التفويض، والروابط العميقة التي تنفّذ عمليات، وغياب دفاعات وقت التشغيل (كشف الروت
  والتلاعب والمصحّح، و FLAG_SECURE)، وسلوك الذكاء الاصطناعي: كل هذا لا تكشفه الفحوص الستاتيكية.
- إصدارات الحزم في نسخة الإصدار من التطبيق مجهولة غالباً، فتأتي نتائج الاعتماديات المصابة في
  حزم التطبيقات بثقة منخفضة. وقائمة التنبيهات منتقاة ومحفوظة محلياً، وليست استعلاماً حياً من OSV.
- لا تُفكّ تطبيقات iOS (‎`.ipa`)؛ يُفحص فقط ملف `Info.plist` في المشروع المصدري.
- تُحلَّل التوقيعات ولا يُتحقق منها تشفيرياً إلا إذا كان apksigner مثبّتاً.
- فئات الجوال (M1 إلى M10 و MASVS) ربطٌ من وضع المشروع انطلاقاً من أرقام CWE.
- جرد واجهات API والمفاتيح (القسم 7) لا يذكر استدعاءات API إلا حيث يوجد نص الكود: المشاريع
  المصدرية ونسخ التصحيح ومخرجات jadx. وفي نسخة الإصدار لا يبقى إلا العناوين ومسارات API المحفوظة
  كنصوص.
- تُعرف خدمة الخادم من جدول ثابت فيه 106 لاحقة لأسماء الخوادم (88 خدمة)؛ وكل خادم آخر يُعدّ
  خادم التطبيق نفسه.
- في الكود المترجم يُعدّ النص الذي هو اسم خادم فقط عنواناً بقاعدة تقريبية (القسم 7: ليس اسم حزمة
  التطبيق نفسه، ولا اسم حزمة معكوساً مثل `sa.gov.absher.app`، والنص المكوّن من جزأين لا ينتهي
  بكلمة تشبه اسم متغير مثل `id` أو `info`). وقد يفوتها خادم، مثل خادم من جزأين تحت `.info` أو
  `.shop`، وقد تعدّ اسماً فيه نقاط خادماً، والعنوان الذي يُركَّب من أجزاء وقت التشغيل لا يُرى
  كاملاً.
- حقول رمز JSON Web Token تُفكّ ولا يُتحقق منها.
- لا تُعرف معرّفات الخدمات إلا بأسمائها وصيغها المشهورة (Firebase و Google و AdMob و Facebook
  و Sentry و Stripe و Mapbox و Supabase وقليل غيرها).
- تحفظ كل قائمة 300 صفّ على الأكثر، والتنبيهات 80؛ والباقي يُعدّ في `truncated`. ويحفظ كل بند
  20 موضعاً على الأكثر، وتُعدّ مواضعه كلها في حقله `count`.
- لا يُفحص شيء عبر الشبكة: لا يُختبر هل قاعدة بيانات Firebase أو حاوية التخزين علنية فعلاً، ولا
  هل المفتاح ما زال يعمل. والتنبيهات تقول ما الذي يجب فحصه.
